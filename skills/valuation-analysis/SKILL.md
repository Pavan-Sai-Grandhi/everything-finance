# Valuation Analysis — intrinsic (DCF) and relative (multiples), reconciled

Read `references/reference.md` first — it owns the method: the life-cycle diagnosis, the levers and where to source each, country risk and beta, the terminal excess-return call, the post-operating adjustments, the capitalisation adjustments, every engine flag, the relative-multiples guardrails, the reconciliation rule, and the DCF-confidence grade. This SKILL is the workflow.

**Sources for this skill only:** `finance-company` — `get_company_fundamentals` (consolidated financials incl. the ten-year cash flow, and the peer list), `get_documents` (annual report and concall as cached local text), `get_stock_ratios` (a peer's own multiples), `run_dcf` (the engine) — and `finance-market` `get_quote` (current price) + `get_prior_run` (step 0).

## Workflow

0. **Check for a prior run.** `get_prior_run(skill="dcf", subject=SYMBOL)` — if `data.path` names an earlier `dcf.md`, read it for context so this valuation stays consistent with the last story, and open the report with a one-line `prior run: <path> (<date>)` link noting what changed (fair value then→now, which assumption moved). No prior run is the normal first-time case.
1. **Gather the sourced base inputs.** `get_company_fundamentals(SYMBOL)` for the ten-year P&L, balance sheet and cash flow, the ratios and the peer list; `get_documents(SYMBOL)` for the annual report, whose **tax note is the only acceptable source for `tax_rate`**; `get_quote(SYMBOL)` for CMP. Both fetches are cached at the tool (fundamentals for the day, documents for good) — call each once and read the `text_path` files, never re-fetch what the cache already holds. The reference's § "The valuation levers" names which published row each input comes from and which must be derived by hand.
2. **Diagnose the life-cycle stage, then build the story.** Set `lifecycle_stage` before any number, then the growth path, margin path, sales-to-capital path, WACC, terminal growth and terminal ROIC, each with a one-line justification. The reference's § "Diagnose first" governs all of it: **terminal growth, country premium, beta and failure probability are conclusions of the diagnosis, never defaults.**
3. **Write the inputs file** from `assets/dcf-inputs.example.yml` → `artifacts/stocks/<SYMBOL>/YYYY-MM-DD/dcf-inputs.yml` (`paths.stock_dir(symbol, date)`), every value carrying a source comment. It is the audit trail for step 4 — the same values go into the tool call.
4. **Run the engine.** `run_dcf(ticker=SYMBOL, inputs=<the file's values>, relative=<the figures from step 6>, sensitivity=true, story=true, reverse=true)` — forward valuation, both sensitivity grids, the reverse DCF and the relative read in one envelope. The full JSON lands at `stocks/<SYMBOL>/<date>/dcf.json`; the response carries the headline numbers plus `dcf_path`. `reverse` solves for **growth** against `current_price` by default; pass `reverse_solve="margin"` for the implied-margin version, or `reverse_target=<price>` to test a different price. An `ok:false` envelope means the model rejected an input (e.g. WACC ≤ terminal growth) — fix the input, never work around the guard.
5. **Read the flags, BOTH grids, and the reverse DCF.** Address every flag raised in the write-up. **Lead with the `story_sensitivity` grid (growth × steady-state margin) as the range**, WACC×g as a secondary check, and read `story_sensitivity.duration` for a premature fade. Then act on the reverse DCF: if the price-implied growth is one no one in the sector has sustained, that *is* the verdict; if it is roughly what the company has already demonstrated and you can name the moat, **lengthen the high-growth window, re-run, and report that as the base case** (extend the duration, never bump the rate). On `solved: false`, read its `reason`.
6. **Build the relative read.** Assemble `relative` = `{pe, peer_pe, own_pe_history, growth}` — the company's P/E, each peer's P/E from `get_stock_ratios(sid)` over the `peers` rows, the company's own historical P/E band, and the expected EPS growth for PEG as a **labelled estimate with its basis stated**. Pass it to `run_dcf`; the returned `relative` block carries the peer median, the P/E-vs-median read, the own-band percentile, PEG and a relative-only stance. Add EV/EBITDA vs peers where capital structures differ — P/B with RoE instead for banks, NBFCs and insurers. The reference's § "Relative valuation" owns the peer-group, median and PEG guardrails.
7. **Reconcile, grade, and call it.** Explain the gap to peers by fundamentals before calling it mis-pricing, grade DCF confidence low/med/high, and weight the two views into one Undervalued / Fair / Overvalued stance — all per the reference's § "Reconcile and grade confidence". Where the run is handed a cap-tier valuation stance, it is context for the relative read only; it never overrides the company's own numbers.

## Produce this report

Fill `assets/dcf-report.example.md` → `artifacts/stocks/<SYMBOL>/YYYY-MM-DD/dcf.md` (`paths.stock_dir(symbol, date)`). Its leading `valuation-block` is machine-read by `deep-analysis`'s portfolio-manager, which cites those numbers without re-deriving them — **keep every field name exactly as the template has it**.

Persist the full report, then return only the `valuation-block` fields plus `path`. A terminal-heavy or fragile DCF is reported with low confidence, never hidden. You inform a decision; you do not size a position.

## Boundaries

A young, loss-making, cash-burning company is **in scope** — that is exactly what story-driven DCF is *for*. Build revenue from TAM × share × take-rate, set the steady-state margin from where the business model lands at scale, fund growth with the sales-to-capital ratio, discount at a country-risk-inclusive WACC, and apply a `failure_probability`. Never refuse a valuation just because earnings are negative today.

DCF is genuinely **fragile** in two cases, where you lean on the relative read and say which you trust and why: **(1) banks / NBFCs / insurers** (FCFF is ill-defined — value on equity/P/B/RoE instead), and **(2) violently cyclical / commodity firms** where fuel, forex, or commodity swings throw FCFF around so hard that any single forecast is arbitrary (normalise through a cycle and treat the DCF as one weak input). Both force the DCF-confidence grade to **low**. The fix for a *young* firm is a failure probability and a story-driver range, **not** abandoning the DCF.

End on the model's own limit: this is a model, not a price target.
